# Writing an article

## Voice

- Живой, неформальный тон, как будто объясняешь коллеге за кофе. Без канцелярита и воды.
- Короткие абзацы, конкретика, личное мнение и опыт — приветствуются.
- Где уместно — вставляй примеры кода (язык по контексту: js/ts/vue/bash и т.д.), с краткими пояснениями до/после блока.
- Заголовки — по делу, не кликбейт.

## Process

1. **Бриф от пользователя.** Пользователь даёт краткое описание/тезисы — это твоя отправная точка, не финальный план.

2. **Уточнение деталей до написания.** Перед тем как начать текст, уточни (если не указано):
   - **title** — заголовок статьи (предложи 1-2 варианта на основе брифа)
   - **slug** — короткий kebab-case идентификатор (предложи на основе title)
   - **date** — дата публикации (по умолчанию можно предложить сегодняшнюю дату)
   - **description** — краткое описание для фронтматтера (1-2 предложения, можно предложить вариант)
   - объём и структуру (список разделов/тезисов), если бриф этого не покрывает

   Не закидывай пользователя всеми вопросами разом без вариантов — предлагай конкретные варианты, чтобы можно было быстро выбрать или поправить.

3. **Пиши статью на русском первой.** Файл: `content/ru/articles/{slug}.md`.

   Фронтматтер (см. `content.config.ts` — схема для коллекции `articles`):
   ```yaml
   ---
   slug: my-article-slug
   title: Заголовок статьи
   description: Краткое описание для превью и SEO
   date: YYYY-MM-DD
   ---
   ```
   После фронтматтера — `# Заголовок` и далее текст с секциями `##`.

   По ходу написания — если возникают развилки (стоит ли углубляться в тему X, нужен ли пример кода для Y, насколько подробно раскрывать Z) — спрашивай у пользователя и предлагай варианты, не додумывай молча за него важные смысловые решения.

4. **После согласования русской версии — перевод на остальные локали.**

   Список локалей бери из `nuxt.config.ts` → `i18n.locales` (на момент написания: `ru` — дефолтная, `en`).
   Для каждой локали, кроме `ru`, создай `content/{locale}/articles/{slug}.md` с тем же фронтматтером (title/description переведены) и переведённым текстом.

   Перевод должен быть естественным для языка, а не дословным — сохраняй тон (живой, неформальный), адаптируй идиомы, проверяй код-блоки (комментарии в коде тоже переводи на английский, если это уместно для англоязычной версии — но сам код не меняй).

5. **Финальная проверка.**
   - Слаги и фронтматтер совпадают по структуре между локалями (кроме переведённых полей).
   - Даты одинаковые.
   - Код-блоки идентичны по содержанию во всех локалях (если не было явного запроса адаптировать примеры).
